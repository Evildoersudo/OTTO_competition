# 数据切分结构

```txt
processed/
│
├── base_train/
│
│   Day1~Day21
│
│   用于：
│   Co-visitation
│   Item statistics
│   NN训练
│
├── ranker_train_hist/
│
│   一部分holdout session的可见前缀
│
├── ranker_train_gt/
│
│   上述session的隐藏未来
│   只用于构造Ranker label
│
├── valid_hist/
│
│   最终validation session前缀
│
└── valid_gt/
    最终validation答案
    只用于Recall@20
```

# 数据流程

```txt
                 原始28天
                    │
           按Session开始时间
                    │
       ┌────────────┴────────────┐
       │                         │
     前21天                    后7天
   base_train                pseudo future
                                 │
                       ┌─────────┴─────────┐
                       │                   │
                    前5天                后2天
                ranker_train          local_valid
                       │                   │
                  session内部          session内部
                   随机截断             随机截断
                       │                   │
                   hist + GT           hist + GT

```


**session之间按照80%+20%的比例按照时间先后顺序切分成ranker_train+local_valid，然后ranker_train和local_valid session的内部，按照时间先后顺序切分**



最后得到的数据结构如下：
```txt
processed/
│
├── base_train/
│
│   Day1~Day21
│   完整历史训练数据
│
├── ranker_train_hist/
│   Day21~Day26 session 的可见前缀
│
├── ranker_train_gt/
│   对应隐藏后缀
│
├── ranker_train_labels/
│   从 gt 提取的 click/cart/order 标签
│
├── local_valid_hist/
│   Day26~Day28 session 的可见前缀
│
├── local_valid_gt/
│   对应隐藏后缀
│
└── local_valid_labels/
    Recall@20 标准答案
```


**后7天内部时间切分的最大价值，是模拟真实线上“用过去预测未来”，避免未来趋势泄漏；随机切分的最大价值，是充分利用数据、提高比赛调参效率。OTTO 第一名复现阶段，我更建议随机；做工业级实验，再补时间切。**
